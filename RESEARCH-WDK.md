## Protocol/storage sources and limits

[ERC-20](https://eips.ethereum.org/EIPS/eip-20) defines indexed Transfer addresses and uint256 value. [Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/) defines receipts/logs/block quantities. [Node SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html) supplies DatabaseSync. The application validates raw ABI widths and stores integer amount strings; confirmations are head minus inclusion block plus one. Canonical inclusion is checked twice by block number/hash, not inferred solely from receipt existence.

Trust remains in the configured RPC and published contract source. This is not a consensus/light-client or receipt-trie proof. Three confirmations are a demo threshold, not economic finality. Reorganizations must be explicitly rechecked; RPC errors preserve last successfully verified credit and report failure rather than fabricating a reorg. Native build provenance beyond registry-integrity/signatures is not independently certified.

Node outbound HTTPS is restricted in this execution environment. The optional project-local PowerShell 7 transport used for live evidence forwards only allowed read methods to the server-configured HTTPS endpoint, via stdin, with timeout/response limits. It is not a system proxy; no certificate validation, firewall, VPN, DNS or Windows network setting was modified. Node fetch remains default; PowerShell must already be available to select that transport. No software is installed automatically.
